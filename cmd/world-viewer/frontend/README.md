# 存档浏览前端

页面用同一个 WebGL 画布显示精细网格、体素远景与小地图。各模块持有自己负责的状态，应用入口负责连接它们，并安排每帧的上传与绘制顺序。

`src/main.ts` 载入样式并启动应用，`src/app/start.ts` 组装存档选择、场景与视图。需要修改一个具体能力时，从对应目录开始：

| 目录 | 职责 |
|---|---|
| `api` | 存档描述、打开进度流和列响应解码；数据契约不依赖 UI 或 three.js |
| `scene` | 主相机输入、精细区块调度、网格生命周期和共享贴图 |
| `terrain` | 区域下载、共享砖池、独立窗口与透视远景 |
| `minimap` | 地图相机、鼠标交互、拾取与占用图 |
| `ui` | 文件选择、诊断、控制面板、坐标与性能状态 |
| `welcome` | 默认场景的取景、漂移、点亮和后处理 |

## 状态和资源归属

一个 `MeshWorld` 持有一代存档的下载队列与精细场景。切换存档时同时取消下载并释放已挂载网格。它报告加载统计、来源诊断和已加载 section，体素远景据此让出精细网格覆盖的位置。贴图由页面级的 `SceneAssets` 跨存档复用，页面结束时统一释放。

`BrickmapWorld` 同时服务地图窗口和主视图远景窗口。展开地图平移只改变地图中心，两个窗口仍复用相同区域的砖与材质。网络完成回调只准备 CPU 数据，GPU 资源的创建、上传和回收都由主帧循环执行。

`FlightControls` 独占主相机的按键和拖动状态。地图展开或接管输入时，应用清空这些状态；相机移动只通知应用刷新加载范围。默认场景的 `Intro` 独占漂移、点亮与视距恢复，打开存档时撤下默认场景的表现。

## 每帧顺序

应用先更新相机和精细加载队列，再确定两个体素窗口的位置并上传完成下载的区域。绘制时先写入远景颜色和透视深度，再让精细场景保留缓冲继续绘制，最后用小地图的 viewport/scissor 覆盖对应屏幕区域。外部 GL 操作结束后交还 three.js 状态。

存档切换和异步贴图载入之间仍使用存档代次判断。已经离开的存档不能在贴图到达后重新挂载网格。页面退出时分别释放各模块拥有的资源；借用共享砖池或贴图的对象先结束使用。

## 开发与内嵌

在本目录运行 `npm test` 和 `npm run build`。开发时运行 `npm run dev`，API 代理到本机的 Go 服务。生成可分发程序时，在 `apps/neomega-viewer` 执行 `go generate ./viewassets`，将生成的 `viewassets/bundle/web` 与源码一并提交，再编译 `cmd/world-viewer`。
